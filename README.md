# 51cto-IPv6及IPv6+网络技术培训课程
获课：jzit.top/26811/


数据中心网络正在经历一次架构层面的代际切换，驱动力不是“协议更新”本身，而是**AI算力集群的流量特征把 EVPN-VXLAN 的结构性短板逼到了台面上**。EVPN 作为控制平面依然稳固，但数据平面的封装方式正在从“UDP套娃”走向“原生 IPv6 指令化转发”。理解这条演进路径，关键不是比较两个协议的功能列表，而是看清一个判断：**VXLAN 解决的是“多租户隔离”问题，而 SRv6 要解决的是“算力效率”问题**。两个时代的需求不同，底座自然要换。

**第一层：VXLAN 在 AI 场景下暴露的是“分流精度”问题，不是隔离能力。**

EVPN-VXLAN 在过去十年很好地完成了它的使命：打破 VLAN 4096 的隔离上限，让虚拟机和容器跨机架漂移成为常态。但大模型训练流量的特征变了。AllReduce、All-to-All 这类集合通信表现为流数极少、单流极大，也就是“大象流”。VXLAN 依赖外层 UDP 源端口做哈希，让 ECMP 去“随机抽奖”式地选路。少量大象流一旦被哈希到同一条物理链路，局部拥塞立刻触发 RoCEv2 无损网络中的 PFC 反压，严重时导致死锁，直接拉低整个集群的算力利用率。这不是 VXLAN 的 bug，是它的设计初衷里没有“显式路径控制”这个需求。而 SRv6 的源路由机制，让路径在起点就被编码进报文，中间节点照单转发，不需要逐跳决策。对于 AI 集群来说，**“我能指定这条流走哪条路”比“网络自动帮我选一条”更有价值**。

**第二层：跨域“协议缝合”是运维复杂度真正的来源。**

数据中心内部跑 EVPN-VXLAN，广域网骨干跑 MPLS 或 SR-MPLS，边界网关必须解封装 VXLAN、剥离标签、再重新封装成 WAN 报文。这个“翻译”动作带来两个后果：状态开销集中在 DCI 网关上，形成单点瓶颈；DC 内部和骨干网的 OAM 机制各管各的，端到端故障定界极为困难。SRv6 的解法是把“网关翻译”变成“普通 IPv6 转发”。在统一的 SRv6 域里，DCI 不再是协议边界，它就是一台普通的 IPv6 路由器，参与同一个 Underlay，不维护逐租户的 VNI，不做 MPLS 标签压入。IETF 的草案里写得很直白：这个模型**移除了传统 VXLAN-EVPN 加 SR-MPLS 设计中必需的 DCI stitching 功能**。运维复杂度的下降，来自协议栈的收敛，而不是加了一层更聪明的网关。

**第三层：演进不是“一刀切替换”，过渡期有明确的过渡期方案。**

现网不可能一夜之间把 EVPN-VXLAN 全部拆掉。IETF 给出了两条过渡路径。第一条是**服务层互通**：边界网关终结一侧的 VXLAN 封装，在另一侧以 SRv6 VPN 服务重新发起，控制面通过 EVPN 与 L3VPN 的路由导入导出完成对接。思科的 NX-OS 已经实现了 EVPN 与 L3VPN SRv6 的平滑 Handoff，VRF 内的路由和 SRv6 SID 在两侧之间传递。第二条是**VXLAN over SRv6**：保留 VTEP 之间的 VXLAN 封装，只用 SRv6 网络来承载 VTEP 到 VTEP 的流量，边界节点不做服务翻译，只做外层封装和转发。这条路径对现有 EVPN 控制面冲击最小，适合那些“先让骨干网跑上 SRv6，DC 内部暂时不动”的场景。选择哪条路，取决于一个判断：**你想在边界做服务终结，还是只想让 SRv6 当一条更可控的传输通道**。

**第四层：真正的长期价值在“服务链”与“算力调度”的咬合。**

SRv6 不只是换了一种隧道封装。它的 SID 可以携带功能指令，防火墙、负载均衡、DPI 这些服务节点可以通过在源路由路径中追加对应的 SID 来动态插入，不需要在中间节点维护逐流状态。这意味着安全策略的变更从“改路由策略”变成了“改路径编排”。更进一步，当算力调度系统需要把流量引导到特定的 GPU 集群或边缘节点时，它可以直接在报文里写入目标 SID，网络设备按指令转发，不需要和网络控制器做复杂的接口对接。Nebius 的实践显示，SRv6 在他们全球网络中把 DC 和 WAN 统一到了一个数据平面上，消除了中间的 stitching 网关。对于正在建设智算中心的企业来说，这意味着**网络不再是算力调度的被动通道，而是可以被算力系统直接编程的转发面**。

归根结底，数据中心从 EVPN 走向 IPv6+ 的演进路径，核心判断只有一条：**VXLAN 的“随机分流”撑不起 AI 集群对确定性转发的需求，而 SRv6 的“源路由指令”让网络从“尽力而为的管道”变成了“可编程的转发面”**。过渡期用网关互通或 VXLAN over SRv6 都能走，但长期方向是统一的 IPv6 Underlay 加上 SRv6 的端到端服务链。工具和芯片的支持节奏会决定落地速度，但架构判断本身已经清晰了。
